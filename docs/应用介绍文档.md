# 企业需求收集与整合系统 — 应用介绍文档

---

## 一、开发背景

在企业日常运营中，各部门（产品、运营、技术、数据等）对内部工具与系统持续产生大量功能需求。这些需求往往呈现以下痛点：

- **碎片化收集**：需求散落在群聊、文档、口头沟通中，缺乏统一的结构化入口，后期难以追溯和统计。
- **重复度高**：不同团队或个人经常提出相似甚至相同的需求，但没有机制去识别和归并，导致研发资源重复投入。
- **优先级模糊**：需求的价值难以量化比较，排期依赖主观判断，高价值需求可能被低优先级需求淹没。
- **信息不透明**：需求提交后缺少状态反馈，提交人不知道需求是否被看到、是否被采纳、何时能上线。
- **外部系统难以对接**：部分需求可能来自工单系统、客服系统等外部渠道，缺少标准化的API对接能力。

基于以上背景，我们构建了本系统，旨在为企业内部提供一个**结构化、智能化、透明化**的需求收集与整合管理平台。

---

## 二、开发目的

本系统的核心目标是解决企业需求管理的四大难题：

| 问题 | 解决方式 |
|------|---------|
| 需求收集碎片化 | 按「栏目」组织需求，提供统一的富文本提交入口 |
| 重复需求难以识别 | 引入 AI 智能分析，自动识别可合并的相似需求 |
| 优先级缺乏量化依据 | 基于预期价值（GMV/效率）、阻塞性、优先级等多维度自动评分 |
| 信息不透明 | 飞书消息自动通知管理员与提交人，状态变更实时触达 |
| 外部系统难对接 | 提供 OpenAPI，支持外部系统通过标准接口提交需求 |

## 三、系统架构概览

### 3.1 技术栈

| 层级 | 技术选型 |
|------|---------|
| 前端 | React 19 + TypeScript + Tailwind CSS + shadcn/ui |
| 后端 | NestJS + TypeScript |
| 数据库 | PostgreSQL + Drizzle ORM |
| 富文本 | Tiptap 编辑器 |
| 表格 | Ant Design Table |
| AI 能力 | AI 文本生成插件（需求合并分析） |
| 通知能力 | 飞书消息发送插件 |
| 部署 | 妙搭全栈应用平台（FaaS） |

### 3.2 角色权限体系

系统采用 RBAC（基于角色的访问控制）模型，核心角色如下：

- **普通用户**：可浏览栏目、提交需求、查看需求详情、发表评论、查看自己的需求列表。
- **需求管理员（demand_admin）**：在普通用户权限基础上，额外拥有栏目管理（创建/编辑/启停）、需求整合（手动/AI整合、添加/释放原始需求、调整分数）、查看全部栏目（含停用栏目）的权限。

角色权限由平台角色面板统一管理，运行时通过 `@CanRole` 装饰器和 `useAuth` Hook 进行前端/后端的双层鉴权。

## 四、核心功能详解

### 4.1 栏目管理（管理员专属）

栏目是需求分类组织的基本单元，对应一个工具或一类工具。

**功能要点**：
- **新建栏目**：管理员填写栏目名称、描述，配置该栏目下可选的「提出部门」列表。
- **编辑栏目**：支持修改名称、描述、部门选项。
- **启用/停用**：停用后普通用户不再看到该栏目，但管理员仍可在管理态查看和操作。
- **自定义部门**：每个栏目可独立配置部门选项，未配置时系统提供默认部门列表。

**数据模型**：`demand_category` 表存储栏目信息，包含 `name`（名称）、`description`（描述）、`enabled`（启用状态）、`departments`（部门选项数组）。

---

### 4.2 需求提交

普通用户在某个栏目下提交新需求，系统会自动截取需求内容前 50 字作为标题。

**需求表单字段**：

| 字段 | 说明 | 必填 |
|------|------|------|
| 需求内容 | 富文本编辑器（Tiptap），支持图文混排、链接等 | 是 |
| 提出部门 | 下拉选择，来源为栏目配置的部门选项 | 是 |
| 需求类型 | 新增功能 / 内容调整 / 优化功能 / 其他 | 是 |
| 预期价值类型 | GMV 提升 / 工作效率提升 | 是 |
| GMV 提升量级 | 仅 GMV 类型时展示（10万以下 ~ 500万以上） | 条件必填 |
| 效率影响人数 | 仅效率类型时展示（10人以下 ~ 500人以上） | 条件必填 |
| 人均节省时间 | 仅效率类型时展示（5分钟以下 ~ 60分钟以上） | 条件必填 |
| 预期上线时间 | 日期选择器 | 是 |
| 优先级 | P0紧急 / P1高 / P2中 / P3低 | 是 |
| 是否为阻塞需求 | 是 / 否 | 是 |

**OpenAPI 提交**：外部系统可通过 `POST /openapi/demands` 接口提交需求，无需登录，但栏目必须处于启用状态。支持传入 `submitterName` 标识外部提交人。

---

### 4.3 需求浏览

进入某个栏目后，以卡片网格形式展示该栏目下的全部需求。

**功能要点**：
- **卡片信息**：需求标题、提交人（内部用户展示头像姓名，外部提交人展示 `submitterName`）、提出部门、提交时间。
- **无限滚动**：采用 IntersectionObserver 实现自动加载更多，每页 12 条。
- **排序**：按提交时间倒序排列，最新需求在前。
- **空状态**：无需求时展示引导，鼓励用户提交第一个需求。

---

### 4.4 需求详情与评论

点击需求卡片进入详情页，展示需求的完整信息。

**功能要点**：
- **元数据展示**：标题、提交人、部门、需求类型、优先级、阻塞状态、预期价值、预期上线时间。
- **富文本渲染**：需求内容以只读模式通过 Tiptap 渲染，保留图片、链接、格式等。
- **评论区**：登录用户可发表评论，评论按时间倒序排列，支持分页加载。
- **状态追踪**：需求状态包括「待处理、跟进中、已完成、已关闭」。

---

### 4.5 我的需求

用户可查看自己提交过的全部需求，以卡片网格展示。

**功能要点**：
- **卡片信息**：需求标题、部门、状态、提交时间。
- **状态标识**：通过 Badge 直观展示当前处理状态。
- **空状态**：未提交过需求时引导用户前往需求广场。
- **跳转**：点击卡片可直接进入需求详情页。

---

### 4.6 需求整合（管理员专属）

需求整合是本系统的核心差异化能力，支持将相似需求合并管理，避免重复开发。

#### 4.6.1 手动整合
- 管理员在整合页进入「选择模式」，勾选 2 条及以上原始需求。
- 填写整合后的标题与整合理由，保存后生成一条「整合需求」。
- 被整合的原始需求不再在广场列表独立展示，而是归并到整合需求下。

#### 4.6.2 AI 智能整合
- 点击「AI 智能整合」按钮，前端调用 AI 文本生成插件（`demand_merge_analyzer`）。
- AI 读取该栏目下全部未整合原始需求，自动识别目标/功能/场景高度相似的需求分组。
- 返回整合建议（整合标题、理由、关联的原始需求 ID 列表）。
- 管理员可勾选采纳多个分组建议，一键保存生成整合需求。

#### 4.6.3 整合需求管理
- **统一表格视图**：原始需求与整合需求在同一表格中展示，按最终分数降序排列。
- **添加原始需求**：可向已有整合需求追加新的原始需求。
- **释放原始需求**：从整合需求中移除某条原始需求，使其重新成为独立需求。
- **自动解散机制**：当整合需求关联的原始需求不足 2 条时，系统自动解散该整合需求。
- **状态管理**：整合需求拥有独立的状态字段（待处理/跟进中/已完成/已关闭）。

**数据模型**：`merged_demand` 表存储整合需求主信息，`merged_demand_source` 表存储整合需求与原始需求的一对多关联关系。

---

### 4.7 需求自动评分

系统为每条原始需求和整合需求自动计算价值分数，辅助管理员判断优先级。

**评分维度与规则**：

| 维度 | 规则 | 分值范围 |
|------|------|---------|
| 预期价值 | GMV 类型按量级 1~5 分；效率类型按影响人数+节省时间各 1~5 分求和 | 1~10 |
| 上线紧迫度 | 预期上线时间与提交时间的间隔，越短分越高 | 1~5 |
| 阻塞性 | 阻塞需求额外加 3 分 | 0~3 |
| 优先级 | P0=4, P1=3, P2=2, P3=1 | 1~4 |
| 整合加成 | 整合需求的最终分 = 关联原始需求平均分 + 关联数量 | 额外加成 |

**分数展示**：
- 系统按最终分数降序对所有需求排名。
- 前 10% 标记为「高优先级」（红色），前 20% 标记为「中优先级」（橙色），其余为「低优先级」（绿色）。
- 管理员可手动调整分数，手动分优先于自动计算分。

---

### 4.8 飞书通知

系统通过自动化触发器与飞书消息插件实现两类通知：

#### 4.8.1 新需求通知（管理员）
- **触发时机**：`demand` 表新增记录（`record_change` 触发器 `demand_created_notify`）。
- **通知对象**：`demand_admin` 角色的全部成员。
- **通知内容**：包含栏目名称、需求标题、提出部门、提交人，以及 AI 自动生成的合并建议（AI 分析该需求与同栏目下其他需求的相似度，给出是否可合并的结论）。
- **交互按钮**：消息卡片附带跳转链接，直达需求整合页。

#### 4.8.2 状态跟进通知（提交人）
- **触发时机**：需求或整合需求的状态被更新为「跟进中」（`record_change` 触发器 `demand_status_followup_notify` / `merged_demand_status_followup_notify`）。
- **通知对象**：原始需求的创建者，或整合需求下全部原始需求的创建者。
- **通知内容**：需求标题、负责人、预计排期。
- **交互按钮**：跳转至「我的需求」页面。

---

### 4.9 OpenAPI 能力

系统提供标准化的对外开放接口，支持外部系统对接。

**接口清单**：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/openapi/demands` | POST | 外部系统提交需求，无需登录鉴权，栏目必须启用 |

**入参字段**：categoryId, title, background, department, submitterName, valueType, gmvLevel, efficiencyAffected, efficiencySavedMinutes, expectedOnlineTime, demandType, isBlocking, priority。

**特性**：
- 外部提交的需求 `creator` 字段为空，通过 `submitterName` 标识来源。
- 提交后同样触发 AI 分析与飞书通知给管理员。
- 与内部提交的需求在广场、详情、整合等场景中无差别展示。

## 五、使用指南

### 5.1 普通用户使用流程

1. **进入栏目列表**（`/`）：浏览当前可使用的工具需求栏目。
2. **选择栏目**：点击进入某个栏目，进入需求广场（`/category/:categoryId`）。
3. **浏览需求**：滚动浏览全员提交的需求卡片，点击卡片查看详情。
4. **提交需求**：点击「提交新需求」按钮，填写表单并提交。
5. **查看进度**：进入「我的需求」页面（`/my-demands`），查看自己提交的需求及处理状态。
6. **接收通知**：当需求状态变为「跟进中」时，自动收到飞书消息通知。

### 5.2 管理员使用流程

1. **栏目管理**：在栏目列表页新建、编辑、启停栏目，配置部门选项。
2. **需求整合**：
   - 进入「需求整合」导航，选择栏目。
   - 在整合页（`/merged-demands/:categoryId`）查看统一表格。
   - 使用「手动整合」勾选相似需求并填写整合信息。
   - 或使用「AI 智能整合」让 AI 自动识别可合并项。
   - 可随时添加/释放原始需求，调整分数。
3. **接收通知**：新需求提交时自动收到飞书卡片通知，含 AI 合并建议。
4. **状态更新**：在整合表格中可直接更新需求状态为「跟进中」，触发提交人通知。

## 六、后续可开发的功能与优化方向

### 6.1 功能扩展

| 方向 | 说明 |
|------|------|
| **需求投票/点赞** | 允许用户对其他人的需求点赞，热度作为排期参考 |
| **需求认领/指派** | 管理员可将需求或整合需求指派给具体负责人，支持飞书人员选择器 |
| **排期看板** | 以看板或甘特图形式展示需求的预计排期与进度 |
| **数据看板** | 统计各栏目需求数量、部门分布、状态分布、平均处理时长等 |
| **评论@通知** | 评论中@用户时，被@人收到飞书通知 |
| **需求导出** | 支持按栏目/状态/时间范围导出需求列表为 Excel/PDF |
| **邮件通知** | 除飞书外，增加邮件通知渠道 |
| **多环境隔离** | 区分测试/生产环境的数据与配置 |

### 6.2 AI 能力增强

| 方向 | 说明 |
|------|------|
| **智能标题生成** | 基于需求内容 AI 自动生成更精准的标题，替代前 50 字截取 |
| **需求分类打标** | AI 自动识别需求类型、优先级建议 |
| **重复度检测优化** | 引入 Embedding 向量相似度，替代纯文本分析，提升合并建议准确率 |
| **自动摘要** | 对长篇需求内容自动生成一句话摘要 |

### 6.3 体验优化

| 方向 | 说明 |
|------|------|
| **搜索与筛选** | 支持按关键词、部门、类型、优先级、状态筛选需求 |
| **排序方式扩展** | 除时间排序外，支持按分数、热度、评论数排序 |
| **批量操作** | 管理员可批量更新状态、批量指派负责人 |
| **草稿箱** | 需求提交前支持保存草稿，下次继续编辑 |
| **图片附件优化** | 当前图片仅支持单张，可扩展为多图上传和缩略图预览 |

### 6.4 系统集成

| 方向 | 说明 |
|------|------|
| **飞书多维表格同步** | 将需求数据同步至飞书多维表格，方便多维分析 |
| **飞书审批对接** | 高优先级需求自动触发飞书审批流程 |
| **JIRA/飞书项目对接** | 需求状态与研发工单系统双向同步 |
| **Webhook 回调** | 支持用户配置自定义 Webhook，在需求状态变更时推送至外部系统 |

| 表名 | 用途 |
|------|------|

| `demand` | 需求主表 |

### 7.3 自动化触发器速查

| 触发器名称 | 触发条件 | 功能 |
